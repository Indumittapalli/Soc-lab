# Suspicious DNS Activity Detection

## Objective

Detect potentially malicious DNS activity that may indicate malware
communication, command-and-control activity, DNS tunneling, or access
to suspicious domains.

## Data Sources

- DNS server logs
- Windows DNS Client logs
- Sysmon telemetry
- Firewall logs
- Network monitoring tools
- EDR telemetry

## Detection Indicators

Look for:

- Queries to known malicious or suspicious domains
- High-frequency DNS requests
- Long or unusually encoded subdomains
- Random-looking domain names
- Large numbers of unique subdomains
- DNS queries generated by unusual processes
- Repeated failed DNS lookups
- DNS requests to newly observed domains
- Unusual DNS record types
- DNS activity occurring immediately before or after suspicious process execution

## Common Suspicious Patterns

### DNS Tunneling

Large amounts of data may be encoded into DNS queries and responses to
create a covert communication channel.

### Command-and-Control Communication

Malware may periodically query attacker-controlled domains to obtain
commands or communicate with a remote server.

### Domain Generation Algorithms

Some malware families generate large numbers of pseudo-random domains
to locate command-and-control infrastructure.

## Investigation Workflow

1. Identify the affected host.
2. Identify the queried domain.
3. Review the frequency and timing of DNS requests.
4. Examine the queried subdomains.
5. Determine which process generated the DNS request where telemetry is available.
6. Investigate the domain and associated IP addresses.
7. Review related network connections.
8. Check for suspicious processes on the endpoint.
9. Search the environment for the same domain or IOC.
10. Map the activity to MITRE ATT&CK.
11. Document findings and recommended response actions.

## IOC Extraction

Potential indicators include:

- Domain names
- Subdomains
- IP addresses
- DNS query patterns
- File hashes
- Process names
